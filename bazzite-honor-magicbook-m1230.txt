BAZZITE — HONOR MAGICBOOK PRO 14 2026 AI (ZQC-P / M1230)
Полный гайд по фиксам
Обновлено: 2026-10-08

ЦЕЛЬ
Поднять на Bazzite:
- ACPI override -> touchscreen + touchpad
- PSR1 -> убрать артефакты PSR2
- HID-BPF micmute -> убрать фантомное mute/unmute
- HID-BPF touchpad edge -> левый край тачпада = яркость
- EgisTec 1c7a:05aa fingerprint
- DSC -> 10-bit / bpp=30 / dither=no
- CDCLK отдельно не патчим: нужный PTL fix уже есть в текущем OGC kernel
- SOF audio отдельно не патчим: нужное обновление уже есть в текущем OGC kernel
- i8042.dumbkbd=1 НЕ добавляем на Linux 7.2+

ВАЖНО
HONOR source tree держим в /opt/honor-magicbook-linux, а не в HOME.
Не запускать apply_patch.sh целиком на Bazzite.
M1230 отсутствует в upstream-профиле репозитория, а часть Tier-B фиксов содержит значения, измеренные на других ревизиях.

1. КУДА КЛАДЁМ HONOR-РЕПО И КАК ОБНОВЛЯЕМ ЕГО БЕЗ ПИЗДЕЦА
============================================================

Репозиторий НЕ держим в $HOME.

Используем:

/opt/honor-magicbook-linux

На rpm-ostree/OSTree системах /opt является machine-local persistent state
(обычно через /var/opt), поэтому Bazzite update его не сносит.

Если старый клон уже лежит в HOME, переносим его:

if [[ -d "$HOME/honor-magicbook-linux/.git" && ! -e /opt/honor-magicbook-linux ]]; then
    sudo mv "$HOME/honor-magicbook-linux" /opt/honor-magicbook-linux
else
    sudo git clone \
      https://github.com/rs0x29a/Linux-on-HONOR-MagicBook-14-Pro-2026-AI_ZQC-P_M1010.git \
      /opt/honor-magicbook-linux
fi

sudo chown -R "$USER:$(id -gn)" /opt/honor-magicbook-linux
cd /opt/honor-magicbook-linux

Проверяем модель:

cat /sys/class/dmi/id/product_name
cat /sys/class/dmi/id/board_version

Ожидается:

ZQC-P
M1230

ВАЖНО: локальный M1230 не держим грязными незакоммиченными изменениями.

git switch m1230-bazzite 2>/dev/null || git switch -c m1230-bazzite

2. СИСТЕМНЫЕ ЗАВИСИМОСТИ BAZZITE
============================================================

Системные RPM layer'им через rpm-ostree.

PERSIST=(
  udev-hid-bpf
  fprintd
  fprintd-pam
)

TEMP=(
  clang
  bpftool
  gcc
  make
  git
  meson
  ninja-build
  pkgconf-pkg-config
  glib2-devel
  libgusb-devel
  nss-devel
  libgudev-devel
  gobject-introspection-devel
  cairo-devel
  pixman-devel
  polkit-devel
  usbutils
)

MISSING=()
TEMP_MISSING=()

for p in "${PERSIST[@]}"; do
    rpm -q "$p" >/dev/null 2>&1 || MISSING+=("$p")
done

for p in "${TEMP[@]}"; do
    if ! rpm -q "$p" >/dev/null 2>&1; then
        MISSING+=("$p")
        TEMP_MISSING+=("$p")
    fi
done

printf '%s\n' "${TEMP_MISSING[@]}" > "$HOME/.honor-temp-layered"

if (( ${#MISSING[@]} )); then
    sudo rpm-ostree install --idempotent "${MISSING[@]}"
else
    echo "Все необходимые пакеты уже есть"
fi

Пока НЕ перезагружаться.

3. ACPI OVERRIDE — TOUCHPAD + TOUCHSCREEN
============================================================

cd /opt/honor-magicbook-linux

Обязательно сравниваем живую I2C_DEVT с заводским референсом:

LIVE=""

for f in /sys/firmware/acpi/tables/SSDT*; do
    [[ -r "$f" ]] || continue

    OEM=$(sudo dd if="$f" bs=1 skip=16 count=8 status=none 2>/dev/null | tr -d '\0 ')

    if [[ "$OEM" == "I2C_DEVT" ]]; then
        LIVE="$f"
        break
    fi
done

echo "Live table: $LIVE"

LIVE_MD5=$(sudo md5sum "$LIVE" | awk '{print $1}')
REF_MD5=$(md5sum dump/acpi/zqc-p/SSDT27_orig.aml | awk '{print $1}')

echo "LIVE : $LIVE_MD5"
echo "REPO : $REF_MD5"

if [[ "$LIVE_MD5" != "$REF_MD5" ]]; then
    echo "STOP: ACPI table отличается. Патч НЕ устанавливаем."
    exit 1
fi

echo "ACPI таблица совпадает — можно ставить."

Устанавливаем AML в /etc:

sudo install -d -m755 /etc/honor-magicbook/acpi

sudo install -m644 \
  patch/acpi-override/zqc-p/M1010/SSDT27_TPD0.aml \
  /etc/honor-magicbook/acpi/SSDT27_TPD0.aml

Создаём dracut config:

sudo tee /etc/dracut.conf.d/90-honor-acpi.conf >/dev/null <<'EOF'
acpi_override="yes"
acpi_table_dir="/etc/honor-magicbook/acpi"
EOF

4. PSR2 -> PSR1
============================================================

Нужен параметр:

xe.enable_psr=1

На Bazzite меняем kernel args через rpm-ostree.

Сначала смотрим:

rpm-ostree kargs

Если уже есть xe.enable_psr с другим значением, удаляем именно его, например:

sudo rpm-ostree kargs --delete="xe.enable_psr=2"

или:

sudo rpm-ostree kargs --delete="xe.enable_psr=0"

Потом добавляем:

rpm-ostree kargs | grep -qw 'xe.enable_psr=1' || \
  sudo rpm-ostree kargs --append="xe.enable_psr=1"

НЕ добавлять:

i8042.dumbkbd=1

На Linux 7.2+ нужный atkbd quirk уже upstream.

6. ПОСЛЕ ПЕРВОГО REBOOT — ПРОВЕРКА ACPI
============================================================

sudo journalctl -k -b | grep -iE 'Table Upgrade|I2C_DEVT|AE_AML_INTERNAL|locked down'

Нужно увидеть что-то вроде:

Table Upgrade: override [SSDT- HONOR-I2C_DEVT]

Не должно быть:

AE_AML_INTERNAL

и:

kernel is locked down, ignoring table override

Если есть "kernel is locked down, ignoring table override":
- Secure Boot / lockdown блокирует override
- отключить Secure Boot в BIOS
- загрузиться снова

Проверка HID устройств:

ls /sys/bus/hid/devices/ | grep -iE '2808:5662|27C6:0F9A'

Должны быть touchscreen и touchpad.

============================================================
10. DSC -> 10-BIT / BPP=30 / DITHER=NO
============================================================

Смотрим текущий статус:

sudo sh -c 'cat /sys/kernel/debug/dri/*/eDP-*/i915_dsc_fec_support'

До фикса обычно:

DSC_Enabled: no
DSC_Sink_Support: yes
Force_DSC_Enable: no

В текущем OGC kernel есть writable i915_dsc_fec_support, поэтому xe.ko не пересобираем.

Создаём helper:

sudo install -d -m755 /usr/local/lib/honor

sudo tee /usr/local/lib/honor/force-dsc.sh >/dev/null <<'EOF'
#!/usr/bin/bash
set -eu

mountpoint -q /sys/kernel/debug || \
    mount -t debugfs debugfs /sys/kernel/debug

for _ in $(seq 1 200); do
    for f in /sys/kernel/debug/dri/*/eDP-*/i915_dsc_fec_support; do
        [[ -w "$f" ]] || continue
        echo 1 > "$f"
        exit 0
    done
    sleep 0.05
done

echo "HONOR: i915_dsc_fec_support not found" >&2
exit 1
EOF

sudo chmod 755 /usr/local/lib/honor/force-dsc.sh
sudo restorecon -F /usr/local/lib/honor/force-dsc.sh 2>/dev/null || true

Создаём systemd service:

sudo tee /etc/systemd/system/honor-force-dsc.service >/dev/null <<'EOF'
[Unit]
Description=Force DSC on HONOR internal eDP panel
After=systemd-modules-load.service
Before=display-manager.service

[Service]
Type=oneshot
ExecStart=/usr/local/lib/honor/force-dsc.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable honor-force-dsc.service

10A. АВТОПРОВЕРКА ПОСЛЕ КАЖДОГО BOOT / BAZZITE UPDATE
============================================================

Делаем маленький health-check. Он НИЧЕГО не патчит и не пересобирает.
Он только проверяет, что после нового deployment наши вещи не исчезли.

sudo install -d -m755 /usr/local/lib/honor /var/lib/honor

sudo tee /usr/local/lib/honor/health-check.sh >/dev/null <<'EOF'
#!/usr/bin/bash
set -u

LOG=/var/lib/honor/health-last.txt
mkdir -p /var/lib/honor
exec > >(tee "$LOG") 2>&1

FAIL=0
ok()   { echo "[ OK ] $*"; }
warn() { echo "[WARN] $*"; }
bad()  { echo "[FAIL] $*"; FAIL=1; }

echo "HONOR M1230 health check"
echo "kernel: $(uname -r)"
echo

KLOG="$(journalctl -k -b --no-pager 2>/dev/null || true)"

if grep -q 'AE_AML_INTERNAL' <<<"$KLOG"; then
    bad "ACPI снова содержит AE_AML_INTERNAL"
else
    ok "нет AE_AML_INTERNAL"
fi

if ls /sys/bus/hid/devices/*2808:5662* >/dev/null 2>&1; then
    ok "touchscreen 2808:5662"
else
    bad "touchscreen 2808:5662 не найден"
fi

if ls /sys/bus/hid/devices/*27C6:0F9A* /sys/bus/hid/devices/*27c6:0f9a* >/dev/null 2>&1; then
    ok "touchpad 27c6:0f9a"
else
    bad "touchpad 27c6:0f9a не найден"
fi

PSR="$(cat /sys/module/xe/parameters/enable_psr 2>/dev/null || true)"
if [[ "$PSR" == "1" ]]; then
    ok "xe.enable_psr=1"
else
    bad "xe.enable_psr=${PSR:-missing}"
fi

if command -v udev-hid-bpf >/dev/null 2>&1; then
    BPF="$(udev-hid-bpf list-loaded 2>/dev/null || true)"
    grep -qi 'honor_ftsc1000_micmute' <<<"$BPF" \
        && ok "micmute HID-BPF loaded" \
        || bad "micmute HID-BPF не loaded"

    grep -qi 'honor_tops0102_edge' <<<"$BPF" \
        && ok "touchpad-edge HID-BPF loaded" \
        || bad "touchpad-edge HID-BPF не loaded"
else
    bad "udev-hid-bpf отсутствует"
fi

PHANTOM="$(
    grep -l UNKNOWN /sys/class/input/input*/name 2>/dev/null |
    xargs -r grep -H 2808 2>/dev/null || true
)"

if [[ -z "$PHANTOM" ]]; then
    ok "phantom KEY_MICMUTE отсутствует"
else
    bad "phantom KEY_MICMUTE вернулся"
    echo "$PHANTOM"
fi

DSC="$(find /sys/kernel/debug/dri -path '*/eDP-*/i915_dsc_fec_support' -print -quit 2>/dev/null || true)"

if [[ -n "$DSC" ]]; then
    D="$(cat "$DSC" 2>/dev/null || true)"

    grep -q 'DSC_Sink_Support: yes' <<<"$D" \
        && ok "DSC sink supported" \
        || bad "DSC sink support пропал"

    grep -q 'Force_DSC_Enable: yes' <<<"$D" \
        && ok "DSC force enabled" \
        || bad "DSC force не включился"

    if grep -q 'DSC_Enabled: yes' <<<"$D"; then
        ok "DSC active"
    else
        warn "DSC сейчас не active (например, eDP ещё не сделал modeset)"
    fi
else
    bad "i915_dsc_fec_support не найден"
fi

DISPLAY_INFO="$(find /sys/kernel/debug/dri -name i915_display_info -print -quit 2>/dev/null || true)"
if [[ -n "$DISPLAY_INFO" ]]; then
    PIPE="$(grep -m1 -E 'pipe src=.*bpp=' "$DISPLAY_INFO" 2>/dev/null || true)"
    if grep -q 'bpp=30' <<<"$PIPE" && grep -q 'dither=no' <<<"$PIPE"; then
        ok "display = bpp=30, dither=no"
    elif [[ -n "$PIPE" ]]; then
        warn "display сейчас не bpp=30/dither=no: $PIPE"
    fi
fi

if [[ -d /opt/honor-libfprint-sdcp ]]; then
    if ldconfig -p 2>/dev/null | grep -q '/opt/honor-libfprint-sdcp'; then
        ok "private SDCP libfprint присутствует в ld cache"
    else
        bad "private SDCP libfprint есть, но ldconfig его не видит"
    fi

    FPUSER="$(getent passwd | awk -F: '$3 >= 1000 && $3 < 60000 && $6 ~ /^\/home\// {print $1; exit}')"
    if [[ -n "$FPUSER" ]] && command -v fprintd-list >/dev/null 2>&1; then
        if timeout 15 fprintd-list "$FPUSER" >/dev/null 2>&1; then
            ok "fprintd видит fingerprint backend"
        else
            warn "fprintd-list не прошёл — fingerprint надо проверить вручную"
        fi
    fi
fi

echo
if (( FAIL )); then
    echo "RESULT: FAIL"
    exit 1
fi

echo "RESULT: OK"
EOF

sudo chmod 755 /usr/local/lib/honor/health-check.sh
sudo restorecon -F /usr/local/lib/honor/health-check.sh 2>/dev/null || true

sudo tee /etc/systemd/system/honor-health-check.service >/dev/null <<'EOF'
[Unit]
Description=HONOR M1230 post-boot health check
After=honor-force-dsc.service honor-hid-bpf-reapply.service display-manager.service

[Service]
Type=oneshot
ExecStart=/usr/local/lib/honor/health-check.sh
EOF

sudo tee /etc/systemd/system/honor-health-check.timer >/dev/null <<'EOF'
[Unit]
Description=Run HONOR M1230 health check after boot

[Timer]
OnBootSec=30s
AccuracySec=5s
Unit=honor-health-check.service

[Install]
WantedBy=timers.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable honor-health-check.timer

После каждого boot результат лежит тут:

============================================================
14. КАК ОБНОВЛЯТЬ BAZZITE, ЧТОБЫ ФИКСЫ НЕ ОТЪЕХАЛИ
============================================================

Почему эта схема переживает обычные Bazzite updates:

- /opt/honor-magicbook-linux -> persistent machine-local source tree
- /etc/honor-magicbook/acpi -> persistent ACPI blob
- /etc/dracut.conf.d/90-honor-acpi.conf -> local initramfs снова включает AML
- rpm-ostree initramfs --enable -> локальная генерация initramfs остаётся включённой
- xe.enable_psr=1 -> kernel arg хранится в deployment config
- /etc/udev-hid-bpf -> HID-BPF объекты persistent и CO-RE
- honor-hid-bpf-reapply.service -> заново цепляет micmute fix на boot
- /usr/local/lib/honor/force-dsc.sh + systemd service -> DSC форсится на каждом boot
- /opt/honor-libfprint-sdcp + /etc/ld.so.conf.d -> fingerprint не лежит внутри /usr
- временные gcc/clang/*-devel после установки удаляем, чтобы они не блокировали будущий rpm-ostree upgrade

ОБЫЧНОЕ ОБНОВЛЕНИЕ BAZZITE:

1. Обновить Bazzite штатно.
2. Перезагрузиться.
3. Через ~30 секунд:

cat /var/lib/honor/health-last.txt

4. Если там RESULT: OK — всё нормально.

Source repo НЕ надо обновлять вместе с каждым Bazzite update.
Установленные фиксы не зависят от того, какой commit сейчас лежит в /opt.

Когда отдельно хочется обновить HONOR upstream:

honor-source-update

После успешного honor-source-update НИЧЕГО автоматически не переустанавливается.
Это специально: новый upstream не должен внезапно заменить уже работающий BPF/libfprint.

Если upstream update задел тот же профиль и rebase конфликтует,
honor-source-update делает git rebase --abort и оставляет старое рабочее состояние.

Если source update прошёл, но новая версия installer тебе не нравится:

cd /opt/honor-magicbook-linux
git reset --hard honor-last-good

Если именно НОВЫЙ BAZZITE deployment сломал загрузку/графику:

rpm-ostree rollback
systemctl reboot

Если новый deployment вообще не грузится:
в GRUB выбрать предыдущий ostree deployment, загрузиться и затем сделать:

rpm-ostree rollback
systemctl reboot

ВАЖНО:
rpm-ostree rollback откатывает OS deployment, но /etc и /var специально persistent.
То есть наши локальные HONOR настройки не исчезают — что здесь как раз и нужно.

НЕ ДЕЛАТЬ без причины:

git pull
git reset --hard origin/main
rpm-ostree reset

Первое может устроить merge поверх локального M1230.
Второе снесёт наш локальный M1230 commit.
Третье удалит все requested layered packages, включая runtime-пакеты,
если они не входят в сам Bazzite image.

ЧТО СПЕЦИАЛЬНО НЕ СТАВИМ
============================================================

1. cdclk-ptl
Не нужен: соответствующий PTL fix уже есть в текущем OGC kernel Bazzite.

2. patch/edp-dsc/install.sh
Не нужен: DSC форсим штатным writable debugfs интерфейсом драйвера, xe.ko не пересобираем.

3. sof-audio
Не нужен на текущем OGC: нужное обновление copier payload уже присутствует.

4. i8042.dumbkbd=1
Не нужен на Linux 7.2+ и отключает нормальный Caps Lock LED.

5. oled-backlight
Не ставить вслепую на M1230.
Floor надо измерять именно на этой панели.

6. fan
Не ставить вслепую на M1230.
EC offsets M1010/M1050 официально не подтверждены для M1230.

7. battery
Не ставить вслепую.
Рабочие EC charge preset пары для M1230 надо сначала проверить.

8. hotkeys / hotkey-actions
Не копировать вслепую с M1010/M1050:
camera USB у M1230 = 30c9:012c, а не 3277:00de.
Сначала отдельно измерить коды кнопок.

9. headset-mic
Отдельный kernel-module quirk для SSID 1ee7:209d не ставим автоматически.

Ставим безопасный updater для исходников:

sudo tee /usr/local/bin/honor-source-update >/dev/null <<'EOF'
#!/usr/bin/bash
set -euo pipefail

REPO=/opt/honor-magicbook-linux
cd "$REPO"

if [[ "$(git branch --show-current)" != "m1230-bazzite" ]]; then
    echo "STOP: expected branch m1230-bazzite"
    exit 1
fi

if [[ -n "$(git status --porcelain)" ]]; then
    echo "STOP: working tree dirty. Ничего не обновляю."
    git status --short
    exit 1
fi

git branch -f honor-last-good HEAD
git fetch --prune origin

if git rebase origin/main; then
    echo
    echo "HONOR source updated successfully."
    echo "Installed fixes НЕ менялись автоматически."
    echo "Сначала проверь diff/README, потом при необходимости перезапускай installer."
else
    echo
    echo "Upstream задел наши M1230 изменения. Автоматически это не склеиваю."
    git rebase --abort || true
    echo "Source tree оставлен на предыдущем рабочем состоянии."
    exit 1
fi
EOF

sudo chmod 755 /usr/local/bin/honor-source-update

Для обновления этого репозитория в будущем использовать ТОЛЬКО:

honor-source-update

Если новый upstream оказался плохим и installer ещё не запускался:

cd /opt/honor-magicbook-linux
git reset --hard honor-last-good

Перед всеми системными изменениями сохраняем текущий рабочий Bazzite deployment:

Это не замена backup, но не даст Bazzite быстро вычистить известный рабочий deployment.

3. ACPI OVERRIDE — TOUCHPAD + TOUCHSCREEN

Обязательно сравниваем живую I2C_DEVT с заводским референсом:

LIVE=""

for f in /sys/firmware/acpi/tables/SSDT*; do
    [[ -r "$f" ]] || continue

    OEM=$(sudo dd if="$f" bs=1 skip=16 count=8 status=none 2>/dev/null | tr -d '\0 ')

    if [[ "$OEM" == "I2C_DEVT" ]]; then
        LIVE="$f"
        break
    fi
done

echo "Live table: $LIVE"

LIVE_MD5=$(sudo md5sum "$LIVE" | awk '{print $1}')
REF_MD5=$(md5sum dump/acpi/zqc-p/SSDT27_orig.aml | awk '{print $1}')

echo "LIVE : $LIVE_MD5"
echo "REPO : $REF_MD5"

if [[ "$LIVE_MD5" != "$REF_MD5" ]]; then
    echo "STOP: ACPI table отличается. Патч НЕ устанавливаем."
    exit 1
fi

echo "ACPI таблица совпадает — можно ставить."

4. PSR2 -> PSR1

Нужен параметр:

xe.enable_psr=1

На Bazzite меняем kernel args через rpm-ostree.

Сначала смотрим:

rpm-ostree kargs

Если уже есть xe.enable_psr с другим значением, удаляем именно его, например:

sudo rpm-ostree kargs --delete="xe.enable_psr=2"

или:

sudo rpm-ostree kargs --delete="xe.enable_psr=0"

Потом добавляем:

rpm-ostree kargs | grep -qw 'xe.enable_psr=1' || \
  sudo rpm-ostree kargs --append="xe.enable_psr=1"

НЕ добавлять:

i8042.dumbkbd=1

На Linux 7.2+ нужный atkbd quirk уже upstream.

Table Upgrade: override [SSDT- HONOR-I2C_DEVT]

AE_AML_INTERNAL

и:

Если есть "kernel is locked down, ignoring table override":
- Secure Boot / lockdown блокирует override
- отключить Secure Boot в BIOS
- загрузиться снова

============================================================
10. DSC -> 10-BIT / BPP=30 / DITHER=NO
============================================================

Смотрим текущий статус:

sudo sh -c 'cat /sys/kernel/debug/dri/*/eDP-*/i915_dsc_fec_support'

До фикса обычно:

DSC_Enabled: no
DSC_Sink_Support: yes
Force_DSC_Enable: no

В текущем OGC kernel есть writable i915_dsc_fec_support, поэтому xe.ko не пересобираем.

Создаём helper:

sudo install -d -m755 /usr/local/lib/honor

sudo tee /usr/local/lib/honor/force-dsc.sh >/dev/null <<'EOF'
#!/usr/bin/bash
set -eu

mountpoint -q /sys/kernel/debug || \
    mount -t debugfs debugfs /sys/kernel/debug

for _ in $(seq 1 200); do
    for f in /sys/kernel/debug/dri/*/eDP-*/i915_dsc_fec_support; do
        [[ -w "$f" ]] || continue
        echo 1 > "$f"
        exit 0
    done
    sleep 0.05
done

echo "HONOR: i915_dsc_fec_support not found" >&2
exit 1
EOF

sudo chmod 755 /usr/local/lib/honor/force-dsc.sh
sudo restorecon -F /usr/local/lib/honor/force-dsc.sh 2>/dev/null || true

Создаём systemd service:

sudo tee /etc/systemd/system/honor-force-dsc.service >/dev/null <<'EOF'
[Unit]
Description=Force DSC on HONOR internal eDP panel
After=systemd-modules-load.service
Before=display-manager.service

[Service]
Type=oneshot
ExecStart=/usr/local/lib/honor/force-dsc.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable honor-force-dsc.service

ЧТО СПЕЦИАЛЬНО НЕ СТАВИМ
============================================================

1. cdclk-ptl
Не нужен: соответствующий PTL fix уже есть в текущем OGC kernel Bazzite.

2. patch/edp-dsc/install.sh
Не нужен: DSC форсим штатным writable debugfs интерфейсом драйвера, xe.ko не пересобираем.

3. sof-audio
Не нужен на текущем OGC: нужное обновление copier payload уже присутствует.

4. i8042.dumbkbd=1
Не нужен на Linux 7.2+ и отключает нормальный Caps Lock LED.

5. oled-backlight
Не ставить вслепую на M1230.
Floor надо измерять именно на этой панели.

6. fan
Не ставить вслепую на M1230.
EC offsets M1010/M1050 официально не подтверждены для M1230.

7. battery
Не ставить вслепую.
Рабочие EC charge preset пары для M1230 надо сначала проверить.

8. hotkeys / hotkey-actions
Не копировать вслепую с M1010/M1050:
camera USB у M1230 = 30c9:012c, а не 3277:00de.
Сначала отдельно измерить коды кнопок.

9. headset-mic
Отдельный kernel-module quirk для SSID 1ee7:209d не ставим автоматически.
Сначала реально проверить микрофон 3.5 mm гарнитуры.
